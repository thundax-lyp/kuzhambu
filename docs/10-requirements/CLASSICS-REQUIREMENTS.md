# Classics Requirements

## Purpose

Classics 古籍域承载平台三类古籍知识库内容和 Portal 已发布稿件展示能力。

本文档按原始需求边界组织，而不是按后台页面区域重新划分：

- 三才图会知识库。
- 王圻文档知识库。
- 明代习俗知识库。

## Scope

覆盖：

- 三才图会 14 个正式门类、106 卷、卷首辅助内容和条目的三级浏览、整理、维护、portal 在线展示、导出和视觉资产生产。
- 王圻相关文档的创建、编辑、阅读、原始文件关联、时间线、单文档问答入口、导出和版本管理。
- 明代习俗专题条目的创建、编辑、筛选、阅读、标签云、导出和版本管理。
- 三才图会、王圻文档和明代习俗的摘要、标签和问答对在内容上下文内联维护。
- 三才图会、王圻文档和明代习俗的草稿、发布和下线生命周期管理。
- 三才图会、王圻文档和明代习俗的异步发布任务、下线任务、进度查看、失败诊断和重试。
- 按权限过滤后的导出内容快照调用 render workers 生成文件产物。

不覆盖：

- AI 服务、模型和提示词配置。
- AI 翻译、标签提取、摘要生成、问答对生成、图片理解和条目拆分的底层执行。
- AI workers 直接调用。
- 跨库搜索排序、查询理解和检索统计事件。
- 跨库知识问答会话和回答生成。
- 知识图谱、实体关系抽取和数据精修工作台。
- 通用文件对象存储、CDN 分发、图片裁剪、图片压缩、水印、视频和音频处理。

### 发布任务

- 必须提供后台专门菜单入口查看发布和下线任务。
- Classics 必须固定提供 5 个职责单一的 Schedule：运行中任务分发、成功终态对账、失败终态对账、ES 残留清理和 FastGPT 残留清理；不得在一个 Schedule 中混合多个目标。
- 一个发布或下线任务只处理一个稿件；批量发布或下线必须拆成多个独立任务。
- 每个稿件只保留最新一条发布或下线任务；发起新任务时只继承旧任务的 ES 文档 ID 和 FastGPT collection ID，并在同一事务内删除同稿件旧任务，不保留任务历史，不继承旧碎片 ID 或清理状态。
- 发起新任务的事务必须锁定同稿件旧 job 后再检查清理状态、继承引用和替换 job；Cleanup Schedule 必须通过同一 job 行上的条件抢占与新任务串行化，禁止旧清理任务删除新任务正在使用的端侧对象。
- 发布任务必须展示任务状态、当前状态过期时间、稿件、开始时间、结束时间、ES 引用、FastGPT collection 引用、碎片数量或可取得的诊断摘要和失败原因；发起人如需展示，从 System 审计记录查询，不得写入 publication job 业务表；不得要求 FastGPT 返回完整 data ID 才能推进任务。
- 发布或下线任务必须由 `job_status` 和 `job_result_status` 共同表达：`job_status` 表示最后一个成功完成的状态机里程碑，`job_result_status` 表示整体运行结果。
- 执行器只执行 `nextStep(job_status)`；成功后推进到已完成里程碑，失败时保持原 `job_status`，不得用 `FAILED` 覆盖失败点。
- 发布状态机必须至少覆盖正式版本快照生成、ES 准备、FastGPT 准备、ES 就绪、FastGPT enable 和稿件状态回填。
- 下线状态机必须至少覆盖 ES 删除态写入、FastGPT collection disable 和稿件状态回填；后续物理删除由定时器垃圾同步清理。
- ES 中的稿件文档必须有独立发布状态，至少支持准备中、就绪和下线删除态；Portal、公开搜索和其他 ES 消费方只能读取 ES 发布状态为就绪的文档。
- FastGPT 发布必须以单个稿件为粒度创建或更新一个 collection，稿件拆分后的多个知识碎片作为该 collection 下的数据片段。
- FastGPT 发布必须使用 collection enable/disable 能力表达该稿件整体是否可召回：准备阶段写入或更新稿件 collection 后保持 disabled，发布就绪后 enable；不得依赖 metadata 表达准备或就绪状态。
- FastGPT 稿件 collection 更新必须是全量替换：通过 `forbid = true` disable collection，按 collection 分页列出并逐条删除全部旧碎片，再写入当前正式版本的完整碎片集合；不得仅 upsert 新碎片或依赖旧任务记录的碎片 ID 清理历史数据。
- Kuzhambu 只确认 FastGPT API 已接受完整碎片集并完成 collection enable/disable，不等待 FastGPT 内部训练、向量化或队列处理完成；内部进度和故障由 FastGPT 自有管理界面负责。
- FastGPT 下线必须先 disable 稿件 collection，让该稿件立即不可召回；collection 和碎片 data 的物理删除必须由定时器垃圾同步清理。
- 发布任务失败后必须保留最后已完成里程碑 `job_status`、`job_result_status`、端侧引用和失败原因；失败点由 `nextStep(job_status)` 确定，只有 `RUNNING` job 可以由 Schedule 自动重试该步骤。
- 发布或下线任务单个状态机切片失败后，必须从失败点自动重试 3 次；初次执行不计入这 3 次重试。
- 状态机切片失败后，当前异步线程必须结束并释放线程资源；后台定时扫描在 30 秒后重新启动线程，重新执行 `nextStep(job_status)`。
- 发布或下线任务失败后不得执行自动回滚；已经成功的端侧操作必须通过任务明细、端侧探测、运行中自动重试和垃圾同步继续收口。
- 发布或下线任务初次执行失败且连续重试 3 次仍失败时，稿件生命周期必须回填为 `ERROR`，业务操作能力等同 `DRAFT` 或 `OFFLINE`。
- 发布或下线任务一旦创建不允许取消；进入 `FAILED` 后不得重新激活原 job，用户只能从稿件页面重新发起发布或下线。
- 无法继续自动重试的失败任务必须保留端侧引用和失败原因，由失败对账、ES 清理和 FastGPT 清理 Schedule 自动收口；不得依赖人工处理。
- 下线任务只有成功完成时，才保证 ES 和 FastGPT 已处于不可见或不可召回状态；下线失败回填 `ERROR` 时不强制外部不可见。
- 发布或下线失败进入 `ERROR` 后可能存在 ES READY 文档、FastGPT enabled collection 等外部残留，后台必须展示最终一致性窗口、外部残留风险、端侧引用和失败原因，并允许用户从稿件页面重新发起发布或下线。
- `ERROR` 稿件再次发布必须按新发布任务重新开始，直接覆盖写入 ES 文档，并按稿件 FastGPT collection 全量替换；不得把端侧探测作为再次发布前置条件。
- Classics 必须提供定时器垃圾同步任务，按 `OFFLINE` 内容、失败发布任务端侧引用和端侧探测结果清理 ES 准备态文档、ES 已删除态残留文档和 FastGPT collection。发布失败 collection 如果仍为 enabled，必须先 disable 再物理删除；删除 collection 必须级联删除其全部碎片 data。
- ES 与 FastGPT 必须使用两个独立清理 Schedule、独立清理状态和独立清理租约。稿件存在时，清理前必须确认稿件仍为 `ERROR` 或 `OFFLINE`、没有运行中过程状态，且待清理 job 仍是当前唯一 job；稿件不存在时，必须确认 job 的 `content_deleted_at` 非空。
- 删除 `ERROR/OFFLINE` 稿件时，必须在删除事务中给 publication job 写入标题快照和 `content_deleted_at`，把有端侧引用的清理状态设置为 `PENDING`，并保留 job；不得通过外键级联删除 job。稿件删除后，Cleanup Schedule 只有在 `content_deleted_at` 非空时才能跳过稿件状态检查并继续清理。
- 垃圾同步任务必须幂等，清理失败只能记录在任务明细或运行日志中，不得改变稿件生命周期。
- 发布任务运行中不得重复发起同一内容的发布或下线任务。
- 发起新的发布或下线任务时，必须先确认同稿件没有运行中任务或运行中端侧清理，再只继承旧任务的 ES 文档 ID 和 FastGPT collection ID、删除旧任务并创建新任务；新任务碎片 ID 必须为空，清理状态必须初始化为 `NONE`。任一清理 Schedule 已认领旧任务时，必须拒绝新任务并提示稍后重试。
- 发布或下线任务运行期间，关联稿件必须禁止编辑、删除、迁移、排序变更和会影响正式版本快照的 AI 结果应用。
- 发布任务完成前，内容不得进入新的最终生命周期状态。
- 稿件生命周期回填是任务最后一个主库状态步骤：发布成功回填 `lifecycle_status = PUBLISHED`，下线成功回填 `lifecycle_status = OFFLINE`，任务失败回填 `lifecycle_status = ERROR`，并清空 `transition_status` 和 `current_publication_job_id`。
- 当前阶段接受 `ES_READY` 到主库回填 `PUBLISHED` 之间的 Portal 和公开搜索提前可见窗口；后续步骤失败时，ES READY 残留由 ES 清理 Schedule 最终清理，不要求实时回滚。
- 稿件运行中控制只使用 `transition_status`，不得增加独立稿件锁字段；`current_publication_job_id` 只表达当前过程状态的任务归属。
- 每次状态机切片开始执行时必须生成新的执行令牌并更新任务过期时间；任务推进必须校验执行令牌。线程必须在任务过期时间前 5 秒停止发起新的端侧调用，端侧调用超时必须小于剩余执行时间并保留 5 秒安全窗口。应用重启、异常中断或失败等待重试时，后台扫描未完成任务，替换过期执行令牌，并通过当前 `job_status` 的端侧探测决定重试、推进或标记失败。
- Scheduler 抢占任务时只写短提交租约，不增加尝试次数；异步线程真正启动后才刷新为切片租约并递增尝试次数。线程池拒绝提交时必须立即释放提交租约且不得计为失败尝试；应用在提交窗口宕机时，由短提交租约过期触发接管。无执行租约统一使用空 `expires_at`，不得使用无限期大数租约。
- 当前阶段不设计发布代次、切片序号或下游 fencing；应用崩溃、JVM 长暂停或远端在客户端超时后继续处理造成的极端迟到副作用作为已接受风险。

### Operations 统计输出

- 必须为 Operations 周报和月报提供聚合后的 summary 只读结果。
- summary 结果必须显式返回 `periodStart` 和 `periodEnd`。
- 周报趋势序列必须按日聚合，月报趋势序列必须按周聚合。
- summary 结果必须包含：
  - `contentCount`
  - `translatedContentCount`
  - `imageReadyContentCount`
  - `visualAssetReadyContentCount`
  - `portalVisitCount`
  - `topContents`：`contentId`、`contentType`、`title`、`visitCount`
  - `contentGrowthSeries`：`bucket`、`createdCount`

## Business Rules

### 三才图会规则

- 自动保存用于防丢，不等同于正式版本。
- 手动保存、AI 结果应用和历史恢复应产生正式版本。
- 条目门类和卷迁移通过选择目标卷完成；条目主表只保存目标 `volume_id`，门类由目标卷所属 `category_id` 决定。
- 条目迁移不改变标签、问答对、图片、视觉资产和历史导出产物。
- 摘要和问答对属于内容上下文内的精修能力，不要求用户进入独立数据精修工作台。
- 新建条目应先进入草稿状态。
- 已发布条目不可退回草稿；需要退出默认可见范围时应通过下线任务下线。
- 下线条目不参与默认列表、搜索、问答、导出和 portal 在线展示。
- 下线条目仍可继续编辑，并可通过发布任务恢复发布。
- 下线条目可在知识图谱中保留来源标记。
- 删除条目前必须二次确认。
- 条目拆分后保存的子条目是独立条目；父条目被删除时不应自动删除已保存子条目。
- 图片缺失不得影响正文阅读，必须显示占位提示。
- 视觉资产必须关联明确三才图会条目。
- 原图和 AI 生成图必须可区分。
- 生图失败不得影响已有原图和历史产物。
- 删除原图或视觉资产产物前必须二次确认。
- 批量视觉资产处理必须复用单条视觉资产流程规则，单条失败不影响其他条目。
- 用户取消批量视觉资产处理后，已完成结果应保留。
- 视觉资产设定集必须包含条目来源、视觉描述、色彩或风格信息、原图和 AI 生成图引用。
- 视觉资产设定集导出前必须按权限过滤关联条目和视觉资产。
- 用户可以选择当前使用版本。
- portal 三才图会展示只展示已发布条目，不生成脱离平台内容状态控制的静态展示包。
- 草稿和下线条目不得进入 portal 展示、公开搜索、问答候选或导出默认范围。

### 王圻文档规则

- 文件替换不得破坏文档正文。
- AI 生成摘要、标签和问答对必须先确认再应用。
- 用户放弃 AI 候选结果时不得修改文档已有内容。
- 摘要和问答对属于文档上下文内的精修能力，不要求用户进入独立数据精修工作台。
- 标签编辑属于文档上下文内的内容维护能力，同时受统一标签体系治理。
- 单文档追加式问答只能围绕当前文档内容组织上下文，不替代跨知识库问答。
- 时间线浏览按文档时间信息排序；文档没有时间信息时按创建时间排序。
- 王圻文档使用草稿、发布和下线生命周期控制公开消费范围。
- 草稿和下线文档不得出现在 portal、公开搜索、问答候选和导出默认范围中。
- 文件缺失时文档正文仍应可阅读。

### 明代习俗规则

- Markdown 必须安全渲染，禁止危险 HTML。
- 习俗详情弹窗必须展示标题、概述、正文、标签和原文摘录。
- 标签云必须基于统一内容标签统计，按标签使用频率体现强弱，点击标签后筛选习俗列表。
- 标签云筛选必须遵守权限过滤。
- 明代习俗使用草稿、发布和下线生命周期控制公开消费范围。
- 草稿和下线习俗不得进入 portal、公开搜索、标签云统计、问答候选或导出默认范围。
- AI 生成结果必须先确认再应用。
- 摘要和问答对属于习俗上下文内的精修能力，不要求用户进入独立数据精修工作台。
- 无标签内容仍可保存。

### 通用内容规则

- 内容权限遵循平台统一权限规则。
- 批量发布和下线必须复用单条发布或下线规则，并遵守当前用户权限。
- 批量发布和下线必须展示成功数、失败数和失败原因，单条失败不得影响其他内容。
- 批量发布和下线发起后不允许取消；每个独立任务必须由运行分发、成功对账、失败对账和端侧清理 Schedule 自动收口为成功或失败。
- 删除内容前必须二次确认。
- 导出前必须按权限过滤内容。
- 导出包含草稿或下线内容时必须二次确认。
- Classics 可以直接调用 render workers 生成 CSV、JSON、HTML 或 ZIP 导出产物。
- Classics 直接调用 render workers 前必须完成用户权限校验、内容状态过滤、非发布内容风险确认和内容快照准备。
- Classics 不得直接调用 workers 的 AI 接口；翻译、摘要、标签、问答对、图片理解、信息融合、视觉描述、条目拆分和生图必须通过 AI 域。
- render workers 返回的文件在进入 Storage 前只是临时产物。
- 过期导出记录不可继续下载。
- HTML 设定集导出模板是随系统发布的静态资源，不属于提示词模块或用户上传内容。
- HTML 设定集模板必须支持数据集元信息、目录、内容正文、离线打开、浏览器打印和 PDF 生成。
- 面向 Operations 的 summary 输出必须以 application result 或 read model 暴露，不得直接复用 Classics admin controller response。
- 内容只使用 `DRAFT`、`PUBLISHED`、`OFFLINE`、`ERROR` 一套生命周期状态，不再维护独立公开或私有可见性；下线状态统一命名为 `OFFLINE`。
- Portal 只读取当前已发布稿件，不提供脱离稿件生命周期的外发快照能力。
- 发布和下线是异步状态机任务。任务运行态使用独立 `job_status` 表达，不得把 `PUBLISHED` 或 `OFFLINE` 当作“正在发布”或“正在下线”。
- 发布任务必须在正式版本快照、ES 稿件发布状态就绪和 FastGPT 同步全部就绪后，才把内容生命周期推进为 `PUBLISHED`。
- 下线任务必须在 ES 稿件发布状态切为下线删除态和 FastGPT collection disable 全部成功后，才把内容生命周期推进为 `OFFLINE`。
- 下线生命周期提交后，ES 物理删除和 FastGPT collection/data 物理删除必须交给定时器垃圾同步任务执行；清理失败不得让内容重新进入可见或可召回状态。
- 发布或下线任务失败时不得自动回滚；失败回填后内容最终生命周期为 `ERROR`，失败时的 `job_status`、端侧引用和失败原因由发布任务记录承载。
- `ERROR` 稿件后台编辑、删除、再次发布或下线操作能力等同 `DRAFT` 或 `OFFLINE`；发布失败产生的 `ERROR` 业务上视为未发布，但发布或下线失败都可能在垃圾同步 Schedule 执行前保留 FastGPT 等外部残留，必须在后台明确提示。
- 内容处于 `PUBLISHING` 或 `OFFLINING` 过程状态时，除发布任务状态机和只读查询外，其他写操作必须根据过程状态拒绝并返回明确原因。
- 已成功写入某个下游端但下一步骤失败时，只要 job 仍为 `RUNNING`，Schedule 必须根据 `nextStep(job_status)` 自动重试；进入 `FAILED` 后不得再执行该步骤，由失败对账和端侧清理 Schedule 自动收口，不需要人工参与。

## Acceptance Criteria

- 用户能从三才图会门类进入卷，再进入具体条目。
- 用户能浏览 14 个正式门类、106 卷和卷首辅助内容。
- 用户能编辑三才图会条目并看到保存状态反馈。
- 用户能通过当前卷内搜索定位三才图会条目。
- 用户能按翻译、配图、视觉资产、完善和生命周期状态筛选三才图会条目。
- 用户能查看多张配图，并区分原图和视觉资产生成图。
- 用户能按原图、理解、融合、描述和生图流程完成视觉资产生产。
- 用户能调整融合权重。
- 用户能查看视觉资产历史产物并选择当前使用版本。
- 用户能发起草稿条目发布任务、已发布条目下线任务，并恢复发布已下线条目。
- 用户能新增王圻文档并维护正文。
- 用户能关联或替换王圻文档原始文件。
- 用户能在王圻文档详情中查看正文、摘要、标签和问答对。
- 用户能触发王圻文档摘要、标签和问答对生成，并在确认后应用。
- 用户能从王圻文档详情发起围绕当前文档的问答。
- 用户能在王圻文档列表浏览和时间线浏览之间切换。
- 用户能按标签筛选明代习俗条目。
- 用户能通过关键词搜索明代习俗条目。
- 用户能打开明代习俗详情并阅读安全渲染后的内容。
- 用户能在内容上下文中维护摘要、标签和问答对。
- 用户能查看和恢复历史版本。
- 下线三才图会条目不出现在默认列表中。
- 用户能当前页多选内容并批量发起发布或下线任务，系统为每个稿件创建独立任务，完成后看到成功数、失败数和失败原因。
- 用户能在专门只读菜单入口查看发布和下线任务状态、端侧引用和失败原因；失败任务不提供重试操作。
- 用户能选择范围和格式后生成导出产物。
- 用户能导出可离线打开的三才图会视觉资产设定集。
- 用户无权导出的内容不会进入导出结果。
- 过期导出记录不可继续下载。
- portal 三才图会页面可按门类、卷和已发布条目逐层浏览。
