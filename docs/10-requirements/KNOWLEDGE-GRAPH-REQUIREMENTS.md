# Knowledge Graph Requirements

## Purpose

本文档定义知识图谱的正式产品需求。图谱展示与探索是核心能力；抽取负责供给素材图谱，编辑负责修订和治理，发布负责将素材知识受控纳入统一图谱。

本文档不定义具体数据库表、字段、索引或 API。这些内容必须在详细设计和接口契约中落实，并不得违背本文定义的产品边界。

## Delivery Calibration

本文件保留产品目标；当前代码完成度以
[`KNOWLEDGE-IMPLEMENTATION-COVERAGE.md`](../40-readiness/KNOWLEDGE-IMPLEMENTATION-COVERAGE.md)
为准，不能由本节的目标性表述反推为已经验收。

- 当前主干已交付 Admin 的工作台、图谱治理、素材管理和提取任务四个菜单入口，以及素材删除变更和删除任务的直达页面；`knowledge:graph:view` / `knowledge:graph:edit` 已同时用于 HTTP 接口和页面动作。
- 当前工作台已交付概览、最近关系的渐进只读画布和活动时间线。全局搜索、质量待办交互、门类层导航及从工作台分流到其他页面仍不是当前 Admin 页面已验证的能力。
- 当前图谱治理已交付发布节点/边 CRUD、来源和操作记录查看、删除影响预览及节点合并；节点拆分和更多接口能力以服务端契约为准，不能仅凭存在路由认定为前端闭环。
- 当前 Portal 已有 `POST /portal/knowledge/graph/material/get` 后端只读接口，Portal Web 已在三才图会稿件详情的“知识图谱”视图消费该接口；未发布、撤回、删除和不可见素材的真实运行时空状态仍待验收。`/knowledge/atlas` 是独立的总谱预览入口，不能替代单稿件图谱的端到端验收证据。
- `graph-result`、`refinement` 等旧 Admin 路由仍在代码中保留兼容入口，虽不在当前图谱菜单 seed 内，也不属于本模型的完成证明。

## Confirmed Product Direction

- 图谱的核心价值是展示、探索、理解关系与追溯来源；抽取和编辑是支撑能力。
- 首期图谱只覆盖三才图会素材。
- 产品以两个数据空间隔离：素材空间保存每份素材的草稿图谱，发布空间保存统一、可展示、可治理的图谱。
- 一份素材只有一张当前草稿图；候选结果可由人工选择合并或整体覆盖草稿图。素材正文更新不自动回写草稿，用户需显式重新抽取。
- 素材图谱整体发布、整体撤回，不提供局部节点或边的发布与撤回。
- 素材中已发布的节点和边冻结为只读；要在素材侧修改，必须先整体撤回该素材，再编辑并重新整体发布。
- 发布空间可独立创建、修改、合并、拆分和删除节点、边，也允许创建跨素材关系；发布空间变更不自动回写素材空间。
- 发布空间允许孤立节点。默认探索画布可不展示孤立节点，但搜索、详情和统计必须可见。
- 每个节点和边都由固化 Schema 定义类型、关系类型和有效 Key 规则。Schema 随代码受控演进，不向用户提供配置或定义查看能力；第一版不以细分属性模型阻断抽取或草稿编辑。
- 素材删除进入素材管理内的删除任务和删除变更入口：删除任务记录后台执行；删除变更按删除时间和版本保留发布相关快照，用户据此选择保留既有发布贡献或撤回本素材关联。
- Classics 是栏目、稿件正文、可见性和生命周期的主事实；Knowledge 只保存 `ContentRef`、标题快照和图谱侧数据，不复制完整稿件。

## Information Architecture

菜单从图谱对象和生命周期组织：

```text
知识治理
└─ 知识图谱
   ├─ 工作台
   ├─ 图谱治理
   ├─ 素材管理
   └─ 提取任务
```

### 工作台

面向全局浏览、发现和待办分流，不承担直接治理编辑。

- 展示已发布节点、关系、覆盖素材、最近发布与最近撤回等统计。
- 默认展示最近发布数据形成的局部图，而不是空画布或全量图：以前端最近成功发布的 100 个节点为种子，查询相关边及其另一端节点，并剔除最终无边的孤立节点。
- 工作台首屏采用“边处理、边渲染”：关联边按批查询；每批返回后立即渲染该批边、补齐并渲染另一端节点，同时更新节点连接度；全部查询完成后移除连接度为零的孤立节点并稳定布局。种子节点在命中首条边前以骨架或淡化状态展示，避免先显示后移除的闪烁。
- 支持全局搜索、局部子图预览、来源追溯和跳转到图谱治理、素材管理或提取任务。
- 展示待处理发布冲突、待治理对象和最近活动。
- 支持鸟瞰层、门类层和详情层浏览，并提供面包屑导航：工作台承担鸟瞰入口，图谱治理承载门类或类型筛选后的局部图，节点或边详情承载详情层。

### 图谱治理

面向发布空间的统一知识维护。

- 支持发布节点和边的 CRUD、局部图探索、对象列表、来源查看和操作记录查看。
- 支持人工创建节点、边和跨素材关系。
- 支持节点合并和拆分；二者属于高风险操作，必须显示受影响属性、关系和素材映射，并留下可追溯操作记录。
- 支持删除；删除节点时必须显式处理其边、素材映射和其他依赖。

### 素材管理

素材管理以用户可见的 Classics 稿件为主列表，再按当页 `ContentRef` 补齐 Knowledge 的图谱侧数据。未创建图谱素材的稿件仍显示为“未初始化/未抽取”，首次发起抽取时才创建素材记录。前端只调用 Knowledge 接口；Knowledge 通过 Classics facade 获取当前用户可见且可图谱化的稿件，不允许前端拼接 Classics 与 Knowledge 接口。

素材列表显示标题、来源类型、卷目/分类、草稿节点数和关系数快照、发布状态、执行中/待审核/失败任务数、最近候选处置、发布贡献、风险提示和最近变更。节点数、关系数和任务摘要均为 Knowledge 的素材统计快照；列表页不得对每行实时聚合草稿节点、关系或任务明细。

单素材图谱页采用“素材正文/证据、图谱画布、对象详情”联动布局：

- 经人工采用的抽取候选进入该素材草稿图，采用方式为合并或整体覆盖；草稿图供人工 CRUD、合并、拆分和修订。
- 未发布对象可编辑；已发布对象只读，提供查看发布结果和整体撤回入口。
- 发布预览和冲突处理在当前画布内完成，不另设割裂页面。
- 仅未发布素材可发起抽取；素材页发起后跳转或定位到提取任务，并在任务完成、候选结果确认后按合并或整体覆盖方式更新当前素材草稿图。
- 支持批量发布操作：用户可一次选择多份素材发起发布，但每份素材仍以自身完整草稿图为唯一范围，独立校验、处理冲突并独立成功或失败；不创建跨素材发布批次或跨素材原子事务。
- 素材详情提供删除预检、删除任务和删除变更入口；删除任务、变更列表不是独立菜单，必须能回到对应素材和发布影响。
- 素材详情使用 `SegmentedDrawer`，固定分为概览、草稿图、提取任务、发布与变更四段。概览显示 Classics 来源、统计快照、风险和最近活动；草稿图只承载草稿编辑；提取任务只承载任务查看与候选处置；发布与变更承载发布、撤回和删除预检。
- 素材库允许批量发起提取、批量发布、批量撤回和批量查看任务。每份素材独立校验、提交和返回结果，不提供批量删除、批量草稿编辑或批量 JSON 导入导出。

### 提取任务

提取任务是图谱抽取记录的查询页，不承担素材草稿编辑、任务创建、候选处置或发布空间治理。默认视图是跨素材的普通任务列表；失败任务仅提供重试操作。

- 仅展示当前用户有权访问的素材和任务；发起单份、整卷或批量抽取的入口保留在素材管理。
- 展示任务运行状态、候选采纳状态、进度、触发来源、输入快照、结果摘要、失败原因、尝试次数、关联任务和清理时间；批量任务必须能定位到每份素材的结果。
- 候选结果可查看对象、关系、告警及其与当前草稿图的差异；候选处置和草稿编辑均在素材详情完成。
- 同一素材最多存在一条 `PENDING` 或 `RUNNING` 任务。服务启动恢复时，原 `RUNNING` 任务先持久化为 `PENDING`，定时同步从 AI 批任务确认仍在执行后才转回 `RUNNING`；AI 暂不可用时保持 `PENDING`。失败任务重试时重置原任务为 `PENDING` 并增加尝试次数；正文、模型或提示词变化后的重新抽取创建新任务，并与来源任务关联。
- 成功任务的候选采用、覆盖、丢弃或被替代后进入处置终态；任务和阶段明细在处置 7 天后物理清理。草稿图、发布记录和最小用户可读摘要不随任务清理而删除。
- 任务详情使用 `SegmentedDrawer` 展示概览、执行和候选结果；关联任务只显示重新抽取来源、替代关系、同批任务和上游触发任务，不把同素材全部历史任务重复塞入详情。

## Publishing Model

### 发布的语义

发布不是复制一份“正式图谱”，而是一次受控合并：素材节点、边通过有效 Key 匹配、创建或关联发布空间对象，并记录素材对象与发布对象的映射。

```text
素材草稿图
  └─ 整体发布
      ├─ 节点/边匹配或创建发布对象
      ├─ 记录素材到发布空间的映射
      └─ 冻结该素材图
```

发布边时必须确保两端存在于发布空间。由于发布粒度为整份素材，端点发布属于同一原子发布批次的依赖处理，不构成额外的用户发布操作。

整体发布以素材当前草稿图为范围。仅当结构不完整、边端点不存在、对象标识重复，或无法计算/人工决定有效 Key 时，整次发布失败，不产生部分发布结果；属性完整性、端点类型兼容、关系限定、环和质量规则只形成提示或治理待办，不阻断第一版发布。

### 发布预览和冲突处理

发布前生成预览，并在画布与右侧面板中展示结果：

- 绿色：将创建发布对象。
- 橙色：将关联既有发布对象。
- 红色：存在必须人工决定的冲突。
- 蓝色：该素材当前已发布且本次不变。

冲突项必须可在画布中定位和高亮。面板只展示做出决策所需的素材对象、候选发布对象、关键字段差异与可选动作。存在未处理冲突时不得确认发布。

用户的冲突决策仅对当前发布批次有效，不沉淀为今后发布的自动匹配规则。

### 发布并发

- 预览采用乐观模式，不长期锁定发布图谱。
- 用户确认时，在一个事务中重新匹配有效 Key、验证命中对象版本并依赖唯一约束防止重复创建。
- 如果预览期间影响本批次的发布对象已被修改、合并、拆分或删除，本次不写入，提示用户刷新预览并重新确认。
- 同一素材在发布或撤回期间进入处理中状态，禁止再次发起发布、撤回或素材侧编辑。

## Extraction Tasks

Knowledge 不得直接调用 AI workers 的图谱抽取接口，必须经 AI 域发起调用。发起前必须校验素材范围、素材状态和用户权限，并使用触发时的素材内容快照。

- 同一素材同一时间只允许一个 `PENDING` 或 `RUNNING` 抽取任务。
- 素材管理展示素材关联任务的统计快照；提取任务展示运行状态、采纳状态、进度、输入快照版本、结果摘要、失败原因、尝试次数、关联任务和清理时间。
- 成功结果先按宽松结构校验生成候选：节点至少具备 ID、类型和名称，边至少具备两端节点引用和关系类型；属性和限定字段允许缺省或开放 JSON。用户确认应用后，可计算 Key 的对象按 Key 合并追加到草稿图；Key 不足或不确定的对象保留为草稿提示，供用户补全后再发布。
- 失败重试必须使用该任务已冻结的内容、模型、提示词和输出 Schema 快照，重置原任务状态并保留尝试历史；仅显式重新抽取创建新任务。
- 已发布素材必须先整体撤回才能抽取。

## Effective Keys and Schema

### Schema Boundary

Schema 是核心竞争力，不公开、不在后台产品化维护。它随代码评审、测试、数据迁移和发布流程演进，并作为以下规则的唯一来源：

- 节点类型、关系类型及其端点兼容建议。
- 可编辑字段、字段类型、多值和质量提示规则。
- 节点和边的身份字段与有效 Key 计算。
- 属性冲突、关系冲突、发布硬校验和质量待办规则。

用户界面展示业务字段和业务化错误提示，不展示 `node_key`、`edge_key`、约束表达式或 Schema 定义。

第一版 Schema 采用“宽接收、严发布”的分层校验：抽取和草稿写入只执行图结构、枚举和基础非空校验，`properties` 与关系限定字段使用开放多值 JSON；属性完整性、关系端点兼容、关系限定、循环和核心关系均作为可见告警或治理待办。发布只阻断会破坏发布空间一致性的结构错误、端点缺失/无效、对象标识重复和无法计算或无法人工决定有效 Key 的情况。

### Key Handling

有效 Key 由 Schema 指定的身份字段系统计算，用户不能直接编辑 Key 文本。

- 普通用户编辑名称、时代、地点层级等业务身份字段，系统实时重新计算 Key。
- 发布时用 Key 精确匹配发布空间对象。
- Key 命中唯一对象时可关联；未命中时可新建；命中多个对象或关键字段冲突时进入发布冲突。
- 边 Key 基于映射后的两端发布节点、关系类型及 Schema 规定的限定字段计算。

## Attributes and Relations

### Multi-value Attributes

发布空间保留具有来源的事实值，不静默覆盖。属性值至少需要表达字段、值、来源类型、来源素材或人工操作、创建时间、状态和是否首选。

Schema 将属性分为：

- 可并存：追加并去重，例如别名、标签。
- 可多值但需首选：可保留多个值，发布展示使用首选值。
- 互斥或身份字段：值不一致时必须进入发布冲突，人工决定保留既有值、采用素材值或回到素材修订。

### Relation Reuse and Conflict

- `edge_key` 完全相同：复用同一发布边，新增素材边到发布边的映射。
- Key 不同且 Schema 允许共存：创建独立发布边。
- Key 不同但 Schema 定义为互斥：进入发布冲突，禁止自动写入。

Schema 定义每类关系的建议端点、Key 组成字段以及可并存或互斥规则；除发布一致性硬约束外，其余规则以告警和质量待办呈现。初期不依赖自然语言语义推理，只使用 Key 精确去重和显式 Schema 规则。

## Quality and Visibility

本期图谱质量指标只包含：

- 孤立节点数。
- 核心节点关系缺失数。

“核心节点”及其要求关系由固化 Schema 定义。工作台和图谱治理按鸟瞰层、门类层展示上述质量指标及对应待治理对象，并可跳转到对象详情或素材管理处理。

发布空间图谱供后台用户浏览与治理；前台不直接浏览发布空间图谱，而是随稿件展示该稿件的图谱内容。搜索和问答不以知识图谱为必需前置。

## Published-space Governance

### Source Types and Manual Objects

发布空间允许人工维护对象。来源标识至少区分：

- `MATERIAL`：由素材发布产生，可追溯到素材映射。
- `MANUAL`：由图谱治理直接创建或补充，不存在可撤回的素材映射。

同一对象可同时具备两类来源。人工创建节点或边必须满足 Schema 的必填身份或限定字段；建议填写维护说明，但不强制提供素材证据。所有人工操作必须保留审计记录。

### Merge and Split

- 合并：选择保留节点，归并属性、关系和素材映射；原映射改指向保留节点。
- 拆分：复制原节点的基础信息，再将属性、边和素材映射明确分配到原节点或新节点；必要时允许复制到两端。
- 拆分必须处理全部受影响关系和映射后才能提交，不能留下身份未确定的半完成结果。

### Published-space Changes and Later Withdrawal

发布空间在素材发布之后发生的更名、属性调整、合并、拆分和人工补充不反写素材。相关操作必须记录。

后续撤回素材时，系统展示该素材发布后相关发布对象发生过的治理改动，提示用户其撤回的是素材贡献，不会抹除后续的全局治理结果。

## Withdrawal and Material Deletion

### Whole-material Withdrawal

撤回按素材整体执行，且只删除本素材对象到发布对象的有效映射。撤回不删除或修改发布节点、发布边、其他素材映射和人工维护内容。

撤回前应展示本素材的关联数量及发布后的治理变更，提示用户撤回的是“本素材贡献”，不会抹除后续全局治理结果。

### Material Deletion Task

删除素材是长期后台异步任务，不是同步删除操作。删除列表与变更列表分开：删除列表只记录素材删除任务；变更列表不承担删除任务管理。

```text
删除预检
  → 创建删除变更项和发布相关快照
  → 用户选择保留发布贡献或撤回素材关联
  → 创建素材删除任务
  → 素材进入删除处理中并锁定
  → 后台按用户选择保留映射或撤回本素材关联，删除素材草稿图、记录结果
  → 完成任务，保留发布和操作历史
```

任务需要持久化状态、执行进度、操作者、开始/结束时间和失败原因，并保证幂等可重试。任务执行中须再次检查依赖，不能依赖预检时的瞬时结果。

成功结果应说明删除草稿图、保留映射或撤回映射的数量。任务失败时保留素材与进度信息，供诊断或重试。

### Material Change List

仅在删除素材时，系统创建素材变更项并保留删除前的发布相关快照。变更列表按素材、删除时间和版本组织，用于让用户理解删除影响并选择后续动作：

- **保留发布贡献**：保留当前发布空间对象与素材映射，不对发布空间执行撤回或清理。
- **撤回素材关联**：按本文件定义的整体撤回规则，删除本素材与发布空间对象的关联。

变更列表需要显示素材、变更时间、版本、变更类型、快照摘要、当前处理状态和用户最终选择。用户选择“保留发布贡献”后仍可从该项重新发起撤回。

## Required Traceability

以下操作必须留存操作人、时间、对象、变更前后或足以恢复的快照、来源或原因：

- 整体发布、整体撤回及其删除的素材关联。
- 发布冲突的本次决策。
- 发布空间人工创建、修改和删除。
- 节点、边的合并与拆分。
- 素材删除任务及其各阶段结果。
- 素材删除变更列表中的快照、用户选择和处理结果。

发布记录必须保存本批次创建、关联、复用、冲突决策和自动补齐端点的结果，以支持后续撤回判断和用户提示。

## Resolved Design Decisions

- 素材删除采用独立删除列表和后台任务；删除时同步创建“变更列表 + 发布相关快照”，按删除时间和版本记录。用户选择保留发布贡献，或撤回素材关联。
- 整体发布中出现结构错误、边端点缺失或无效、对象标识重复，或有效 Key 无法计算且用户未作决定时，整次发布失败；其他 Schema 告警不阻断发布。
- 发布后草稿原地锁定；发布批次保存审计快照，不创建草稿版本。
- 发布空间删除节点时，必须显式选择级联删除关联边，或先解除依赖；映射保留历史状态。
- 工作台默认按最近发布数据展示局部图。
- 本期不定位节点、边到素材正文的具体证据碎片。
- 图谱抽取由素材管理发起、在提取任务中执行和审看；候选结果确认后按合并或整体覆盖方式写入素材草稿图。支持一次选择多份素材发起批量发布，但每份素材独立发布，不形成跨素材发布批次。
- 失败任务在保留冻结输入的前提下原地重试；成功任务必须经合并采用、覆盖采用、丢弃或替代后才可清理。处置终态任务及其阶段明细在 7 天后清理。
- 素材列表以 Classics 可见稿件分页结果为基础，Knowledge 批量补齐素材、统计快照和任务摘要；前端不调用其他域接口拼装图谱页面。
- 权限沿用系统既有 `module + domain + view/edit` 定义，图谱菜单、页面和动作按本文档的权限映射授权。
- 工作台以最近成功发布的 100 个节点为种子，按边处理、边渲染的方式补齐关联节点；最终局部图最多渲染 200 个节点，边随节点集合返回，不单独设置边数量上限。
- 本期仅支持单份稿件图的 JSON 文件下载与上传；不提供发布空间整体图谱的导入导出。
- 世系图专用提取、展示及覆盖指标明确不纳入本期。

## Remaining Detail Decisions

以下不是产品方向未定，而是进入详细设计时必须精确定义的行为：

1. 素材删除变更列表的快照字段、状态流转，以及用户选择“保留发布贡献”后再次发起撤回的交互。
2. 候选结果差异预览和稿件图 JSON 的具体字段、Schema 校验、失败报告格式。
3. 最近发布局部图超过 200 节点时的截断提示和继续展开方式。

## Acceptance Criteria

- 用户能在素材管理中浏览自己可见的 Classics 稿件，即使尚未初始化图谱素材；列表显示 Knowledge 的统计快照和任务摘要，且前端不需要调用 Classics 接口拼装数据。
- 用户能在素材管理中对未发布素材触发图谱抽取，并在提取任务中查看运行状态、采纳状态、进度、失败原因、取消和重试入口；候选结果经确认后按合并或整体覆盖方式写入该素材草稿图。
- 同一素材同时至多一条 `PENDING` 或 `RUNNING` 任务；失败重试重置原任务并增加尝试次数，已处置任务及其阶段明细在 7 天后清理。
- 用户能在素材和任务 `SegmentedDrawer` 中分别查看来源、草稿、统计、任务摘要，以及执行阶段、候选差异、处置记录和关联任务；候选处置不直接编辑草稿图。
- 用户能在素材管理完成草稿节点和边的新增、编辑、删除、合并和拆分；已发布素材的草稿对象只读，必须整体撤回后才能编辑或再次抽取。
- 用户能选择单份或多份素材发起整体发布；每份素材独立校验、预览冲突和确认结果，不形成跨素材原子发布。
- 存在未处理的 Schema、Key、属性或关系冲突时，受影响素材不得发布；用户能在画布中定位冲突并完成关联、新建或返回修订的决定。
- 整体发布成功后，系统创建或关联发布节点和边、记录素材映射并冻结该素材草稿；发布边的两个端点均存在于发布空间。
- 用户能整体撤回某素材，系统只删除该素材关联，不删除或修改发布空间对象、其他素材关联和人工维护内容。
- 用户删除素材时，系统创建可跟踪、可重试的后台删除任务与删除变更快照；选择保留发布贡献时，系统须在删除草稿前固化可追溯来源快照，不得留下指向已删除草稿对象的关联；用户能查看最终结果。
- 用户能在图谱治理中对发布空间节点、边和跨素材关系进行 CRUD、合并、拆分和删除，并查看来源素材与操作记录；合并和拆分必须完整处理受影响关系和素材映射。
- 工作台展示最近成功发布的 100 个节点及关联局部图，按边处理、边渲染渐进展示，最终剔除孤立节点；用户能在鸟瞰层、门类层和详情层之间导航。
- 工作台和图谱治理展示孤立节点数、核心节点关系缺失数及对应待治理对象；前台仅在稿件通过既有内容可见性校验且素材已发布时展示该稿件图谱，不直接浏览发布空间、未发布草稿或治理数据。
- 不具备 `knowledge:graph:view` 或 `knowledge:graph:edit` 的用户不能分别访问图谱读取或修改动作；所有高风险修改保留影响预览、二次确认和审计记录。
- 用户能下载单份稿件图的 JSON 文件，并上传 JSON 到未发布草稿图；上传不满足 Schema 时返回可定位的校验错误；用户不能导入或导出发布空间整体图谱。

## Permission Mapping

权限沿用既有 `module + domain + view/edit` 模型，不增加“发布者”“治理者”等新角色或额外权限码。图谱功能归属 Knowledge 模块、graph domain：

| 页面或动作 | 权限 |
| --- | --- |
| 工作台、图谱治理、素材管理、提取任务，以及素材管理内删除任务、删除变更的浏览、搜索、来源和操作记录查看 | `knowledge:graph:view` |
| 素材草稿 CRUD、抽取、稿件图下载和上传 | `knowledge:graph:edit` |
| 素材整体发布、整体撤回、变更列表处理、素材删除和删除任务重试 | `knowledge:graph:edit` |
| 发布空间节点/边 CRUD、人工对象、跨素材关系及发布对象删除 | `knowledge:graph:edit` |
| 节点/边合并和拆分 | `knowledge:graph:edit` |

所有高风险 `edit` 操作必须提供影响预览、二次确认和审计记录；权限控制不替代这些交互保障。
