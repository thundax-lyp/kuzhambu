# System Implementation Coverage

## Purpose

本文档记录 System 域需求的当前实现覆盖状态，用于后续补充开发、跨域协作和验收确认。

本文档不替代 `docs/10-requirements/SYSTEM-REQUIREMENTS.md` 和 `docs/30-designs/SYSTEM-DESIGN.md`。

## Status Definition

- `已完成`：需求可在当前仓库里形成可追溯交付物，并可由运行时代码闭环支持。
- `部分完成`：核心模型或服务已就绪，但有关键场景缺少 API、策略、联调或观测闭环。
- `未完成`：仓库当前未形成可执行设计、数据结构或明确任务。
- `外部依赖`：能力边界不属于 System，或运行职责在其他域完成。

## Current Baseline

已完成：

- System 采用 `kuzhambu-system-domain / application / infra / interface` 四层实现，模块边界清晰，权限、会话、审计链路可独立维护。
- 认证链路已落地：预认证会话、验证码、登录 token/refresh token、登录/刷新/登出、失败记录。
- 业务用户与登录标识分离（user / principal identity）模型已在领域完成，敏感凭据不落数据库明文。
- 会话、token、登录事件、认证事件已具备持久化/缓存实现，支持刷新、失效、回收、事件记录。
- 用户、角色、菜单、部门、字典等后台管理能力具备完整增删改查与分页查询接口。
- 菜单排序、显示控制、可见性、角色菜单关系已支持，个人菜单/权限查询可直接反映当前用户上下文。
- 当前用户信息与个人配置（基本信息、头像）已支持。
- 审计日志域/接口完整，支持日志类型查询、对象筛选、详情和字段级变更输出。
- 登录与认证事件、权限、审计链路有接口契约测试覆盖，当前入口路径和响应字段结构稳定。
- 本轮已完成 Classics 内容域权限资源对齐：三类内容 view/edit 权限、通用分享编辑权限和通用内容导出权限已被后端运行态和 Admin Web 控件共同消费；`db/data-source/system.json` 与 `db/data/system.sql` 经 `node scripts/generate-system-data-sql.ts --check` 验证一致。
- Portal 端为公开展示内容，不提供通用鉴权入口，认证上下文复用不作为 Portal 目标覆盖项。
- portal 不提供通用审计查询入口，当前行为与 `SYSTEM-REQUIREMENTS` 的边界一致。

部分完成：

- 统一权限判断与“隐含资源点”覆盖存在差距：核心功能具备 `@HasPermission`，Classics 内容域权限闭环已补齐；后续新增管理端入口仍需按同一资源点治理方式持续补齐。

未完成：

- 无（该项与需求边界一致，当前未纳入 System 统一约束）。
